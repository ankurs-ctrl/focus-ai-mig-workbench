### 3. Correct recovery and retry behavior

The investigation reproduced these defects:

- A completed saved receipt can still contain old unresolved table references. Recovering it can overwrite newer verified references.
- Clearing the recovery notice can hide controls while reference polling does not restart.
- Reselecting the same file after a terminal failure can keep recovering the failed request instead of permitting a fresh attempt.
- The nominal 60-second polling deadline can be exceeded by individual requests.

Required behavior:

- Recovered preview and enrichment state must be consistent and version-aware.
- Never replace newer verified state with older receipt data.
- Continue observation automatically while appropriate; clean up timers and requests on unmount.
- Bound each request by the remaining observation deadline.
- Permit explicit retry after confirmed terminal failure while retaining failure history.
- Preserve caller/project isolation and prevent stale workers from publishing.
- Do not confuse closing a dialog with cancelling server processing.

### 6. Fix the two previously deferred SQL-upload defects

#### A. Column substitution corrupts function names

Reproduction:

```sql
WITH c AS (
    SELECT ID AS LENGTH, NAME
    FROM D.S.T
)
SELECT LENGTH AS A, LENGTH(NAME) AS B
FROM c;
```

A shared bare-name binding map can rewrite the function identifier `LENGTH` as though it were a column, producing an invalid expression such as:

```sql
cte_c.LENGTH(c.NAME)
```

Behavior can depend on projection order, while local readiness checks may accept the result.

**Fix:** use SQL-aware binding/rewriting that distinguishes functions, columns, aliases, literals, comments, and quoted identifiers. Avoid global regex substitutions across unrelated scopes.

Location: `frontend/src/features/sttm/mapping/sql-upload-workspace.ts`, previously around lines 307 and 356–361.

#### B. Case-sensitive quoted sources collapse when reopening

These are distinct Snowflake objects:

```sql
D.S."Country"
D.S."country"
```

The reopen path uppercases source identities during deduplication. A saved graph with two sources and a join can become one source with no join, potentially compiling incorrect SQL.

**Fix:** preserve quoted-identifier case and relation-instance identity through selection, serialization, reopening, and compilation. Only normalize identifiers where Snowflake’s unquoted-identifier rules permit it.

Location: `frontend/src/features/sttm/store/sttm-builder-slice.ts`, previously around lines 6566–6569.
