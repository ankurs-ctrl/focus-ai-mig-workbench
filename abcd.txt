Make Auto-map produce grounded results as context grows

## Summary

The deployed failure has three independent causes. For mapping 2702, mandatory CTE parent closure pulled roughly 600 `ACCOUNTS` columns into a bounded message, so ten targets reached **zero model calls**. For mapping 2803, the model received eligible `COUNTRY_CODE` and `COUNTRY_ALIAS` columns but incorrectly claimed none were available; `HOUSEHOLD.BILLINGCOUNTRY ← COUNTRY_CODES.COUNTRY_CODE` is the known positive control. Two other completed responses were discarded because the terminal parser rejected `suggested_queries`.

Keep the existing staged orchestrator. Change its **evidence contract and decision stages**, then prove a positive mapping in UAT. More workers alone cannot resolve these failures. Accuracy takes priority over a hard three-minute deadline; insufficient evidence must remain explicit rather than become a guessed mapping.

## Implementation changes

1. **Make validated CTE outputs the source boundary.** At job preparation, verify that the current SQL, output schema, and parent dependency hashes match a successful server validation; revalidate once if that proof is missing or stale. Expose only the CTE’s output columns as selectable sources. Keep original SQL, parent columns, joins, filters, and provenance in the immutable archive for targeted checks and final compilation. A hidden parent column must never become a selectable CTE output. For large physical tables without a CTE, page column evidence instead of requiring an indivisible whole-table message.

2. **Separate candidate discovery from mapping decisions.** Build a complete, indexed source inventory once per request, including distinct self-join bindings. Combine current semantics, applicable FIR and published precedents, exact SQL lineage, and Cortex Search candidates. Rank candidates per target, but retain all originals and a coverage cursor; a shortlist is not evidence that other columns do not match. Scan additional pages when a target has no supported candidate or a credible alternative remains unread. Present the model with small target groups and an explicit `selectable_sources` list; put nonselectable table, lineage, and target metadata in separate sections without misleading `eligible=false` source-like cards. Size every serialized call against both existing message limits.

3. **Use bounded, parallel decision and rule calls.** Decide source bindings per target or small compatible group, carrying exact evidence IDs and plausible alternatives in strongest-first order. Detect factual contradictions such as “no eligible columns” when the admitted roster is nonempty, and make one focused repair call with the exact target and candidate roster. Do not promote a lexical match on its own. Once a binding is grounded, generate any needed complex expression in a separate bounded `AGT_TRANSFORMATION_RULE` call; the current fast path skips that specialist. Validate source scope, value bindings, SQLGlot syntax, and compiled mapping SQL before applying a result. Preserve valid rows if another target or rule fails.

4. **Repair transport and expose coverage.** Apply the narrowly tested `suggested_queries` parser correction: accept it only as well-formed inert metadata alongside a completed answer, while continuing to reject tool blocks, unknown content, ambiguous completion, and suggestion-only responses. Track per target whether source inventory, learning evidence, CTE contract, model decision, and transformation validation were completed. Return a grounded mapping, a reviewable proposal, or a specific unresolved reason. Maintain `candidate_source_attributes`, confidence and reason, and existing manual and published mapping protections. Log sizes, counts, stages, and failure types without raw SQL or semantic text. Snowflake documents evolving Agent content and advises clients to handle unknown streaming events; answer extraction must remain strict even as ancillary content varies. [Cortex Agents Run API](https://docs.snowflake.com/en/user-guide/snowflake-cortex/cortex-agents-run)

Run a project-501 canary, then review target-level accuracy, rule execution, message sizes, model calls, latency, and unresolved reasons before enabling the path more broadly. A green unit suite without a successful live positive mapping is not acceptance.
