### Issue: Publishing a mapping incorrectly requires target-table INSERT permission

**Cause:** Before saving a published mapping to metadata, the application validates its generated `INSERT` statement using `EXPLAIN`. Although this does not insert any data, Snowflake still checks INSERT permissions on the target table.

For Smit’s publication, this failed because the application’s restricted-caller configuration lacks `CALLER INSERT` on:
`FFP_HDP_DLAB_MIG_WORKBENCH_DB_UAT.TARGET_TABLES.BIZ_CONTACTS`.

**Impact:** Publication is blocked even though it should only store mapping definitions and SQL in metadata. The UI misleadingly reports a SQL compilation problem instead of the underlying permission failure.

**Required correction:** Adjust publication validation so metadata-only publishing does not require target-write permission. Validate execution permissions separately when the migration is actually executed.

**No target rows were inserted by the failed validation.**
