1. Prepare Configuration
Ensure client.env contains:
SNOWFLAKE_SEMANTIC_VIEWS_DATABASE=FOCUS_DB_2
SNOWFLAKE_SEMANTIC_VIEWS_SCHEMA=STTM_MCP
SNOWFLAKE_SEMANTIC_TABLE_VIEWS_TABLE=SEM_TABLE_VIEWS
SNOWFLAKE_SEMANTIC_COLUMN_VIEWS_TABLE=SEM_COLUMN_VIEWS
SNOWFLAKE_SEMANTIC_NATIVE_VIEWS_TABLE=SEM_NATIVE_VIEWS
The importer reads services\sttm-builder\.env.local, so create it locally:
Copy-Item `
  .\infra\snowflake\env\client.env `
  .\services\sttm-builder\.env.local `
  -Force
Do not commit either environment file.
2. Prepare Python Once
py -3.11 -m venv .\services\sttm-builder\.venv

.\services\sttm-builder\.venv\Scripts\python.exe `
  -m pip install -e .\services\sttm-builder
Confirm FIR was deployed before the task failure:
SHOW AGENTS LIKE 'AGT_FIR_SYSTEM' IN SCHEMA <METADATA_DB>.<METADATA_SCHEMA>;
SHOW PROCEDURES LIKE 'SP_FIR_INVOKE_AGENT' IN SCHEMA <METADATA_DB>.<METADATA_SCHEMA>;
3. Check Semantic Compatibility Views
The current FIR procedures read these lightweight latest-record views:
SHOW VIEWS LIKE 'LATEST_%' IN SCHEMA FOCUS_DB_2.STTM_MCP;
You should see:
LATEST_TABLE_VIEWS
LATEST_COLUMN_VIEWS
LATEST_NATIVE_VIEWS
These do not copy semantic data. They select the latest active row from your existing SEM_* tables. If they are absent, the script can still be stored and published, but semantic-grounded FIR learning should wait until the views are created.
4. Dry Run the Import
Run once per mapping. Supply authoritative fully qualified physical tables:
$python = ".\services\sttm-builder\.venv\Scripts\python.exe"

& $python .\scripts\load_client_fir_knowledge.py `
  --project-id "401" `
  --mapping-name "Household Migration" `
  --mapping-description "Historical household migration imported from client SQL" `
  --business-goal "Create the curated household target" `
  --file "C:\ClientMappings\household.sql" `
  --source-table-hint "SOURCE_DB.CRM.ACCOUNTS" `
  --source-table-hint "SOURCE_DB.CRM.CONTACTS" `
  --target-table-hint "TARGET_DB.CURATED.HOUSEHOLD" `
  --create-mapping `
  --publish `
  --dry-run
Use --project-name, --project-description, --project-domain, and --project-outcome instead of --project-id when creating a new project.

5. Perform the Actual Import
Run the same command without --dry-run:
& $python .\scripts\load_client_fir_knowledge.py `
  --project-id "401" `
  --mapping-name "Household Migration" `
  --mapping-description "Historical household migration imported from client SQL" `
  --business-goal "Create the curated household target" `
  --file "C:\ClientMappings\household.sql" `
  --source-table-hint "SOURCE_DB.CRM.ACCOUNTS" `
  --source-table-hint "SOURCE_DB.CRM.CONTACTS" `
  --target-table-hint "TARGET_DB.CURATED.HOUSEHOLD" `
  --create-mapping `
  --publish `
  --rebuild-search
To create physical secure views for named CTEs, add:
--materialize-ctes
Use that only when the role can create the derived views and the CTE SQL is executable in the client environment. Nested CTEs, comments, joins, filters, windows, and transformations are learned as evidence even without materialization.
6. Manually Run FIR
Because tasks cannot run yet, execute this in Snowsight or Snow CLI:
ALTER SESSION SET STATEMENT_TIMEOUT_IN_SECONDS = 3600;

CALL <METADATA_DB>.<METADATA_SCHEMA>.SP_FIR_COLLECT_FEEDBACK();

CALL <METADATA_DB>.<METADATA_SCHEMA>.SP_FIR_ENRICH_CONTEXT(100);

CALL <METADATA_DB>.<METADATA_SCHEMA>.SP_FIR_INVOKE_AGENT(
  OBJECT_CONSTRUCT(
    'task_type', 'document_learning',
    'batch_size', 100,
    'processing_options', OBJECT_CONSTRUCT(
      'collect_feedback', FALSE,
      'generate_inferences', TRUE,
      'create_semantic_versions', TRUE,
      'generate_recommendations', TRUE,
      'parse_documents', TRUE,
      'apply_decay', FALSE
    )
  )
);

CALL <METADATA_DB>.<METADATA_SCHEMA>.SP_FIR_SCORE_RECOMMENDATIONS();
The FIR agent call can take several minutes. It does not require EXECUTE TASK; it requires permission to call the procedures and agent. Snowflake allows procedures to be invoked directly using CALL. Snowflake procedure documentation
7. Verify Learning
SELECT *
FROM <METADATA_DB>.<METADATA_SCHEMA>.TBL_FIR_ASSET_TABLE_REFERENCES
ORDER BY CREATED_AT DESC;

SELECT INFERENCE_TYPE, SUMMARY, CONFIDENCE, STATUS
FROM <METADATA_DB>.<METADATA_SCHEMA>.TBL_WORKBENCH_INFERENCES
ORDER BY CREATED_AT DESC;

SELECT TARGET_AGENT, TRIGGER_TYPE, DISPLAY_MESSAGE, CONFIDENCE
FROM <METADATA_DB>.<METADATA_SCHEMA>.TBL_FIR_AGENT_RECOMMENDATIONS
WHERE STATUS = 'active'
ORDER BY CREATED_AT DESC;
For multiple CRM mappings such as Accounts, Contacts, Notes, and Household, run the importer separately for each mapping. That gives every source set and target its own published STTM and exact context_key, allowing the UI and Auto-map to retrieve the correct precedent later.
