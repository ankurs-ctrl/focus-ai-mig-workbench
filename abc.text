We reviewed the July 20–22 Snowflake usage. The environment consumed 83.39 credits, of which 82.32 were virtual-warehouse compute credits. Approximately 71% of the total three-day usage occurred on July 22.
The main issue was that the Medium warehouse was being used for both heavy validation workloads and frequent lightweight operations such as metadata discovery, refresh, autosave, semantic/FIR retrieval, polling, stored procedures, agent-support queries, and manual testing. Medium consumes four times the hourly credits of an X-Small warehouse. Because these short operations occurred throughout the day, the warehouse remained active or repeatedly resumed even though users were not continuously using the application.
The report attributes the usage across both direct user activity and the application: ANKURSINHA and SMITSHAH account for approximately 52.6 estimated credits combined, while the web application service account represents approximately 21.5 credits. Because the previous release did not include detailed workload query tags, these numbers cannot yet distinguish every application feature from manual or Snowsight activity.
We have implemented the following corrective actions:
Routine control and metadata work is routed to X-Small compute.
Medium is reserved for explicit preview, validation, data-quality, test, publish, and DBT execution.
Semantic bundles and FIR learning context are cached and reused.
Concurrent duplicate requests are coalesced.
Repeated connection-health SQL has been removed.
Large SQL and semantic YAML are stored once as secured artifacts rather than repeatedly sent through agent conversations.
Agent conversations automatically roll over while preserving context, preventing oversized repeated prompts.
Workload-specific query tags, timeouts, resource monitors, and cost dashboards have been added.
Warehouses will use short auto-suspend settings and separate cost thresholds.
Following deployment, we will compare query history and warehouse metering against the previous release. The target is at least an 80% reduction in routine SQL volume, with the Medium warehouse remaining suspended unless a user explicitly performs a heavy execution or validation operation.
