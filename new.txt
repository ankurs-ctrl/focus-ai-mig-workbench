Yes. Send IT/admin this SQL template. They should replace the placeholders in <...>.
This assumes these already exist: compute pools, image repository, external access integration, app roles/service roles basics. This SQL focuses on OAuth + secrets + required grants.
USE ROLE ACCOUNTADMIN;

-- =========================================================
-- 1. Create / replace OAuth integration
-- =========================================================
CREATE OR REPLACE SECURITY INTEGRATION <OAUTH_INTEGRATION_NAME>
  TYPE = OAUTH
  ENABLED = TRUE
  OAUTH_CLIENT = CUSTOM
  OAUTH_CLIENT_TYPE = 'CONFIDENTIAL'
  OAUTH_REDIRECT_URI = 'https://<CLIENT_SPCS_APP_HOST>/api/v1/auth/callback'
  OAUTH_ALTERNATE_REDIRECT_URIS = (
    'http://localhost:3000/api/v1/auth/callback'
  )
  OAUTH_ISSUE_REFRESH_TOKENS = TRUE
  OAUTH_REFRESH_TOKEN_VALIDITY = 86400
  OAUTH_ENFORCE_PKCE = TRUE
  OAUTH_USE_SECONDARY_ROLES = IMPLICIT
  PRE_AUTHORIZED_ROLES_LIST = (
    '<APP_ADMIN_ROLE>',
    '<APP_PUBLISHER_ROLE>',
    '<APP_VIEWER_ROLE>'
  )
  BLOCKED_ROLES_LIST = (
    'ACCOUNTADMIN',
    'SECURITYADMIN',
    'ORGADMIN',
    'GLOBALORGADMIN'
  );

DESC SECURITY INTEGRATION <OAUTH_INTEGRATION_NAME>;

SELECT SYSTEM$SHOW_OAUTH_CLIENT_SECRETS('<OAUTH_INTEGRATION_NAME>');
Admin will get OAUTH_CLIENT_ID and OAUTH_CLIENT_SECRET from the last command. Then run:
-- =========================================================
-- 2. Store OAuth client credentials as Snowflake secret
-- =========================================================
USE DATABASE <APP_DB>;
USE SCHEMA <APP_SCHEMA>;

CREATE OR REPLACE SECRET <APP_DB>.<APP_SCHEMA>.STTM_BUILDER_OAUTH_CLIENT_CREDENTIALS
  TYPE = PASSWORD
  USERNAME = '<OAUTH_CLIENT_ID_FROM_SYSTEM_SHOW>'
  PASSWORD = '<OAUTH_CLIENT_SECRET_FROM_SYSTEM_SHOW>';

-- Session signing/encryption secret.
-- Use strong random values generated by admin/security.
CREATE OR REPLACE SECRET <APP_DB>.<APP_SCHEMA>.STTM_BUILDER_OAUTH_SESSION_KEYS
  TYPE = PASSWORD
  USERNAME = '<RANDOM_64_CHAR_SESSION_SECRET>'
  PASSWORD = '<RANDOM_32_OR_64_CHAR_ENCRYPTION_KEY>';
Then grant the service owner/deploy role access to secrets:
-- =========================================================
-- 3. Secret access for SPCS service owner role
-- =========================================================
GRANT READ ON SECRET <APP_DB>.<APP_SCHEMA>.STTM_BUILDER_OAUTH_CLIENT_CREDENTIALS
  TO ROLE <SERVICE_OWNER_ROLE>;

GRANT READ ON SECRET <APP_DB>.<APP_SCHEMA>.STTM_BUILDER_OAUTH_SESSION_KEYS
  TO ROLE <SERVICE_OWNER_ROLE>;

GRANT USAGE ON DATABASE <APP_DB> TO ROLE <SERVICE_OWNER_ROLE>;
GRANT USAGE ON SCHEMA <APP_DB>.<APP_SCHEMA> TO ROLE <SERVICE_OWNER_ROLE>;

Most important values you need back from IT:
OAUTH_INTEGRATION_NAME
OAUTH_CLIENT_ID
OAUTH_CLIENT_SECRET
SNOWFLAKE_OAUTH_AUTHORIZE_URL
SNOWFLAKE_OAUTH_TOKEN_URL
confirmed redirect URI
secret names:
  <APP_DB>.<APP_SCHEMA>.STTM_BUILDER_OAUTH_CLIENT_CREDENTIALS
  <APP_DB>.<APP_SCHEMA>.STTM_BUILDER_OAUTH_SESSION_KEYS
Your client.env should then use:
AUTH_MODE=custom_oauth
SNOWFLAKE_OAUTH_CLIENT_SECRET_OBJECT=<APP_DB>.<APP_SCHEMA>.STTM_BUILDER_OAUTH_CLIENT_CREDENTIALS
SNOWFLAKE_OAUTH_SESSION_SECRET_OBJECT=<APP_DB>.<APP_SCHEMA>.STTM_BUILDER_OAUTH_SESSION_KEYS
SNOWFLAKE_OAUTH_AUTHORIZE_URL=https://<account_host>/oauth/authorize
SNOWFLAKE_OAUTH_TOKEN_URL=https://<account_host>/oauth/token-request
SNOWFLAKE_OAUTH_REDIRECT_URI=https://<CLIENT_SPCS_APP_HOST>/api/v1/auth/callback
SNOWFLAKE_OAUTH_SCOPE=session:role-any
If the SPCS host changes after deploy, IT only needs to run:
ALTER SECURITY INTEGRATION <OAUTH_INTEGRATION_NAME>
SET OAUTH_REDIRECT_URI = 'https://<NEW_CLIENT_SPCS_APP_HOST>/api/v1/auth/callback';
