# Requested changes to Auto-map candidates, suggestions, and review

Auto-map should continue applying valid AI proposals to the **editable mapping draft**. Users should review, compare, and change those proposals directly in the mapping sheet. Applying an AI proposal must **not** confirm, finalize, or publish the mapping.

The following changes should improve the layout, distinguish real alternatives from general guidance, and make the recommendations easier to understand.

## 1. Move all row-level AI information into the Source Column cell

The **Target Column** cell should display the target column name and its normal metadata only.

Move the following information into the **Source Column** cell, directly below the currently mapped source column or columns:

- AI review status.
- **View candidates**.
- **Suggestions**.
- Candidate confidence, reasoning, and relevant warnings.
- Actions such as **Use candidate**, **Confirm mapping**, **Undo AI change**, and **Clear suggestion**.

The selected source must remain the primary information in that cell. Candidate details and suggestions should be collapsed by default to avoid excessively tall rows.

**Example layout:**

```text
Source Column

ACCOUNTS.ADDRESS1_LINE1
AI suggested — not reviewed

View candidates (1)    Suggestions (1)
Confirm mapping       Undo AI change
```

Keep expanded content within the Source Column cell’s width, wrap long identifiers sensibly, and avoid expanding the Target Column cell.

## 2. Show only genuinely different alternatives under “View candidates”

The current mapping should not appear again as an alternative to itself.

For an already mapped row:

- Hide **View candidates** when there are no different mapping options.
- Show it when another source column or combination of columns is suggested.
- Also show it when the source columns are the same but the transformation is meaningfully different.

For example, these are different candidates:

- `ACCOUNTS.NAME` using a **Direct** mapping.
- `ACCOUNTS.NAME` using **TRIM**.
- `ACCOUNTS.NAME` using **UPPER(TRIM(...))**.

However, the same source and transformation with a different explanation or confidence score is **not** a separate candidate.

Candidate comparison must consider the complete mapping definition: source identities, mapping mode, transformation, Value or placeholder, and required dependencies. Do not compare display strings alone.

**Additional rules:**

- The button count must reflect only the alternatives actually displayed.
- Show up to three genuine alternatives; do not manufacture options to fill the list.
- Keep the current mapping’s confidence and reasoning accessible beneath the selected source, even when there are no alternatives.
- A current mapping that requires revalidation should show that status directly—not appear as a duplicate candidate merely to offer an “Apply” button.

## 3. Separate mapping candidates from informational suggestions

**Candidates** and **suggestions** serve different purposes and should have separate sections.

### View candidates

Use this section for concrete alternative mapping definitions, such as:

- A specific source column or combination of columns.
- The same source with a different transformation.
- A complete approved Value or placeholder mapping.

Each candidate should display:

- **Source column(s)** or **Value**.
- **Mapping type**.
- **Transformation**, where applicable.
- **Confidence**, when supplied.
- **Why this option was suggested**.
- **Relevant limitations or prerequisites**.

A candidate with unresolved prerequisites may be shown as **Requires join**, **Requires Value**, or **Needs rule validation**, but its **Use candidate** action must remain disabled until those prerequisites are satisfied.

### Suggestions

Use this section for guidance that is not yet a complete mapping option:

- No suitable source was found.
- A potentially relevant column is empty or has poor coverage.
- Additional tables, relationships, or lookup data are needed.
- A business rule or Firm Value must be provided.
- A referenced source is outside the current selection.
- More evidence is required before a mapping can be proposed.

Do not generate an empty candidate such as:

```text
0% · Direct
No source columns
Unresolved — cannot select
```

Show that information under **Suggestions** instead. Absence of a proposal should not be presented as a fabricated **0% confidence** candidate.

A column mentioned in explanatory prose is not automatically a candidate. For example, “`SI_FIRM` is entirely null; consider a firm lookup” is guidance, not an applicable mapping definition.

### Join recommendations and navigation

Where a suggestion identifies a required relationship, provide a **Review suggested join** action.

That action should:

1. Open the existing **Select Tables** page for the current mapping.
2. Open the relationship or join-definition editor.
3. Preselect the recommended source tables or existing relation instances.
4. Prefill the proposed join type and conditions **when supported by evidence**.
5. Identify the target mapping that needs the join and explain why.
6. Require the user to review and explicitly save the join.

For example:

```text
Suggested relationship

Purpose: Resolve the firm identifier for TRANSACTION_FIRM__C.
Tables: ACCOUNTS and the recommended firm lookup.
Condition: Display the proposed matching keys, if established.

Review suggested join
```

Do not invent table names, join keys, or join types when the evidence does not establish them. In that case, open the editor with the known information and clearly identify what the user must complete.

Preserve existing tables, aliases, joins, filters, CTEs, and unsaved mapping changes. Do not silently save a relationship, change the driving table, or rerun Auto-map.

After the user saves the join, return to the affected mapping row and offer to **Reevaluate this mapping**.

## 4. Improve formatting and make explanations row-specific

Replace long, repetitive paragraphs with concise, structured details.

Use a consistent presentation:

> **Source:** `ACCOUNTS.SI_REVIEWFREQUENCY_FORMATTEDVALUE`  
> **Mapping:** Direct  
> **Confidence:** **82%**
>
> **Why suggested**
> - Contains readable review-frequency labels.
> - Aligns with the target’s review-cadence meaning.
>
> **Considerations**
> - Highlight the relevant null rate or coverage limitation.
> - State whether a fallback or business decision is needed.

Formatting rules:

- Use monospace for exact **table names, column names, placeholders, and SQL expressions**.
- Bold **confidence scores, percentages, project names, statuses, and important actions**.
- Use short bullets for reasoning and separate bullets for limitations.
- Explain technical validation messages in plain language, with raw details available through an expandable section.
- Remove duplicate warnings.
- Show only warnings relevant to that row or candidate.

Do not attach another target’s warning to the current row—for example, a referral-data warning should not appear beneath an address mapping unless it genuinely affects that mapping.

Render formatting safely. Agent-provided text must not be treated as unrestricted HTML.

## 5. Restore a moderately detailed, structured AI Assistant summary

The AI Assistant should provide more than a one-line count, while leaving the actual review controls in the mapping sheet.

Use the following structure:

### Auto-map results

Summarize:

- Targets evaluated.
- New draft mappings applied.
- Existing definitions retained.
- Rows with alternative candidates.
- Rows still unresolved.
- Rows requiring validation or business input.

These categories can overlap; label them clearly rather than presenting them as mutually exclusive totals.

### Notable mappings and alternatives

Highlight a small number of useful examples:

- What source was selected and why.
- Where a meaningful alternative exists.
- Important differences between alternatives.
- Confidence or coverage limitations worth reviewing.

Provide a **View row** link that opens the relevant row and expands its candidates or suggestions.

### Suggestions and next actions

Group recommendations by action:

- **Relationships to review**.
- **Firm Values or business rules required**.
- **Source-data limitations**.
- **Mappings requiring closer review**.

### Review reminder

End with a short statement such as:

> These changes are saved as draft suggestions. Review the highlighted rows before confirming or publishing.

Do not restore a second “accept all candidates” workflow in chat. Candidate selection remains in the sheet.

Generate counts from the resulting mapping state, not from model-written prose. Distinguish **retained definitions** from **validated mappings**, and avoid duplicate completion messages.

## 6. Replace generated hash aliases with accurate, user-friendly names

User-facing content should not display generated aliases such as:

```text
accounts_enueh8.SI_REVIEWFREQUENCY_FORMATTEDVALUE
```

Display the resolved table and column name instead:

```text
ACCOUNTS.SI_REVIEWFREQUENCY_FORMATTEDVALUE
```

Apply this consistently to:

- Selected source columns.
- Candidate details.
- Suggestions and warnings.
- Confidence explanations.
- AI Assistant summaries.
- Transformation explanations.
- Join recommendations.

### Preserve executable identity

This must be an **identity-aware display change**, not a global string replacement.

Internally, retain the canonical relation ID, executable alias, and exact column identifier required for SQL generation and validation.

Resolve friendly names through the current source/relationship metadata. Do not simply remove a suffix that looks like a hash: legitimate table names and user-authored aliases may contain similar text.

When a table appears more than once, use a meaningful role or authored alias to distinguish it, for example:

```text
ACCOUNTS (Household).NAME
ACCOUNTS (Parent account).NAME
```

When necessary, show `SCHEMA.TABLE.COLUMN` or provide the full qualified name in a tooltip.

For CTEs, display the authored CTE name.

Both `AGT_SOURCE_MAPPING` and `AGT_TRANSFORMATION_RULE` should receive the distinction between **execution references** and **display names**. Their structured outputs must remain precisely bound to real sources; the application should enforce consistent friendly rendering rather than relying solely on agent wording.

Do not silently rewrite executable SQL just to make the display prettier.

## 7. Keep the previous mapping available when an alternative is applied

When a user selects another candidate:

- The chosen candidate becomes the current mapping.
- Remove it from **View candidates** because it is now selected.
- Move the previous mapping into the alternatives list, provided it is a meaningful, distinct mapping.
- Preserve its original confidence, reasoning, transformation, and dependencies.
- Label it **Previously applied**.
- Update the candidate count immediately.

**Example:**

Before switching:

```text
Current: ACCOUNTS.ADDRESS1_LINE1 — Direct — 85%

View candidates (1)
ACCOUNTS.ADDRESS1_COMPOSITE — Direct — 72%
```

After switching:

```text
Current: ACCOUNTS.ADDRESS1_COMPOSITE — Direct — 72%

View candidates (1)
Previously applied:
ACCOUNTS.ADDRESS1_LINE1 — Direct — 85%
```

For a manually authored previous mapping, show **Manual mapping** and **Confidence not available** if no AI confidence exists. Never invent a score or explanation.

Revalidate candidates before applying them, particularly if joins, Values, or source selections have changed.

Persist the selected mapping, alternatives, explanations, and review status across autosave and reopening. Preserve **Undo AI change** independently so confirming the current option does not destroy the earlier undo point.

## Acceptance criteria

The change is complete when:

- All row-level AI details appear beneath the source—not the target.
- The current mapping is excluded from its own alternatives.
- Same-source, different-transformation options remain available.
- Empty or guidance-only responses appear under **Suggestions**, not candidates.
- Join recommendations open a prefilled, reviewable editor without saving automatically.
- User-facing identifiers are readable and unambiguous, with execution bindings preserved.
- Candidate switching retains the previous mapping and its original explanation.
- The AI Assistant provides a structured summary with accurate counts and useful next actions.
- Existing authored mappings, SQL, CTEs, joins, filters, and Values remain protected.
- Applying a candidate changes only the draft; confirmation and publishing remain separate actions.
