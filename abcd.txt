## Remaining findings

### 1. CTE wrapper processing can silently change query meaning — high priority

**Location:** `services/sttm-builder/app/core/automap_cte_contract.py:26–37`

The wrapper check examines SELECT-level modifiers but misses modifiers attached to the source table.

Probes showed it accepts wrappers containing:
- `SAMPLE (0)`, which changes the selected population.
- A positional column alias, which changes output names.

Hydration then strips those modifications and validates the replacement.

**Recommendation:** Only unwrap a demonstrably transparent wrapper. Inspect source-table modifiers and alias-column lists; preserve or reject anything that changes rows or output columns.

### 2. Specialist model-envelope validation still fails open — high priority

**Locations:**  
`services/sttm-builder/app/core/automap_specialist.py:18–24`  
`services/sttm-builder/app/core/sttm_builder.py:6521–6526`

Provider-level completion checks now work. However, the specialist then uses the legacy envelope parser, which defaults unknown statuses to `COMPLETED`.

With otherwise valid rules, probes accepted:
- `data.status = "in_progress"`
- Root-level `status = "failed"`
- A string-valued error indicating rule generation failed

Those responses became accepted complex mappings.

**Recommendation:** Strictly validate the specialist’s raw model envelope before normalization. Explicit failure, nonterminal or unknown status, conflicting statuses, and malformed error fields must not become completed rules.

### 3. Specialist uncertain-call recovery uses the wrong agent identity

**Location:** `services/sttm-builder/app/core/automap_runtime.py:664–677`

Specialist dispatch uses its own backend, but the recovery bundle retains the source-mapping backend. Recovery compares the stored specialist agent identity against the source agent and rejects it.

In otherwise equivalent lost-acknowledgment probes:
- Source call: recovered and released.
- Specialist call: rejected before recovery and remained quarantined.

**Recommendation:** Bind recovery to the actual backend used for the original call, while retaining all request, caller, permit, and agent-identity checks. Do not simply remove the identity check.

Quarantine remains safe, but repeated affected calls could leave model capacity unavailable until operator intervention.

### 4. An unrelated CTE can block a valid selected source

**Location:** `services/sttm-builder/app/core/automap_cte_contract.py:18–21`

A positional output alias in an **unused** top-level CTE causes the entire preparation to fail—even when the selected CTE does not depend on it.

**Recommendation:** Apply unsupported-definition checks to the selected CTE’s reachable dependency set, rather than rejecting unrelated definitions globally.
