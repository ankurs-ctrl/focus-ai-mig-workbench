## 2. Cross-cutting decisions

### Parallelization matrix
| Parallelize | Keep sequential |
|---|---|
| The ~11 learning sub-queries **after** `_get_link_scope` | `_get_link_scope` first (feeds linked ids) |
| `semantic` ‖ `learning` in `prepare._build` | The agent stream (single LLM call) |
| Autosave analytics writes → background | Core snapshot write before the STTM `UPDATE` referencing it |
| (client already parallel) attributes ‖ relationships | DDL / `ensure_storage` |

**Constraint:** Snowpark `Session` is not thread-safe for concurrent queries → use a **small connection pool, one connection per worker thread**.

### Warehouse allocation (one Medium available)
| Workload | Target | Rationale |
|---|---|---|
| **CONTROL** | **Medium** | Runs the FIR recs proc + the parallel learning fan-out + autosave. *Biggest win — the slow procs are tagged `control`.* |
| **AGENT** | **Medium** | Cortex analyst/agent tool SQL (~4–5s) on the interactive path |
| **EXECUTION** | **Medium** | SQL preview / derived-source validation |
| **AUTOMAP** | keep **XS** | Batch — must not contend with interactive |

**Make the Medium multi-cluster (MIN 1 / MAX 3).** Parallelizing learning sends ~11 concurrent queries at CONTROL; a single cluster would re-serialize them. (Your XS is already `MAX_CLUSTER_COUNT=3` — match it.)

## 4. PHASE 1 — CODE DROP 1 (the structural wins)

### 1.1 Remove `SP_GET_TABLE_RELATIONSHIPS` from the hot path — *highest value / lowest risk*
- **Where:** `table_selection.py:327-333` (the `if not payload and len(tables) <= 3` fallback).
- **Why safe:** **[LIVE]** your source schemas have **PRIMARY KEYs but zero FOREIGN KEYs**; the proc reads only FKs → it returns empty 100% of the time. Output is identical to today.
- **How:** delete/flag-gate the fallback. For tables with `HAS_LOW_CONFIDENCE_JOINS=TRUE` (29%), make a **product decision**: surface low-confidence joins with a "needs review" badge, or show none — but don't call a 5s empty proc.
- **Gain:** −3.5–7s on the relationship step. **Rollback:** env flag to re-enable.

### 1.2 Parallelize the learning fan-out — *biggest latency lever*
- **Where:** `learning_retrieval.py:370-451`.
- **How:** run `_get_link_scope` first; then execute the remaining ~11 independent calls in a `ThreadPoolExecutor` (size ~6–8) with a **connection pool** (one connection per worker). Preserve result-merge order and existing L1/L2 caching + build locks.
- **Gain:** ~16s → ~max(single) ≈ 9s now, **≈2s** after 2.1.
- **Risk:** thread-safety (handled by the pool) + connection pressure (bounded by pool size). **Rollback:** flag `LEARNING_PARALLEL_ENABLED=false`.

### 1.3 Run `semantic ‖ learning` in `prepare`
- **Where:** `prepared_context.py:313-369`. Two independent stages → run concurrently, merge results.
- **Gain:** cold `prepare` ≈ max(semantic, learning) instead of the sum.

### 1.4 Defer autosave analytics writes to background
- **Where:** `project_service.py:1260-1376`.
- **Keep synchronous:** snapshot INSERT → sources → mapping rows → STTM `UPDATE`.
- **Move to background:** `_record_agent_artifacts`, `_record_autosave_fir_events`, `knowledge_projector.project`, `_record_target_mapping_patterns`, `upsert_feature_snapshot`.
- **Guardrail:** add **retry + logging** so deferred learning writes can't silently vanish.
- **Gain:** ~12s → ~2–3s. **Rollback:** flag to run inline.

### 1.5 Frontend streaming render
- **Where:** `ai-agent-panel.tsx:188-404`, `sttm-builder-slice.ts:3566`.
- **How:** `React.memo` `MessageContent`; `useMemo` the parsed blocks (parse only new content); **throttle/batch** token dispatch on a ~50 ms / rAF tick.
- **Gain:** removes O(n²) re-parse; smooth long streams.

## 5. PHASE 2 — CODE DROP 2 (depth + the caching gap)

### 2.1 Optimize `SP_FIR_GET_AGENT_RECOMMENDATIONS`
- Profile it (`GET_QUERY_OPERATOR_STATS`); 6–11s implies full scans. Add clustering / pre-aggregation / tighter predicates on the FIR tables.
- **Keep it in the agent prompt** — parallelize (1.2), don't defer it out. *See §6.*
- **Gain:** the parallel fan-out's ceiling drops from ~9s to ~1–2s.

### 2.2 Fix prepared-context **L2 persistence** *(new — from the cache evidence)*
- **[LIVE]** only 4 rows, last write Jul 28 → the durable tier isn't filling, so caching is effectively per-process L1. **This matters more once `MAX_INSTANCES=2`** (each instance warms separately).
- Investigate whether the persist path is gated/failing under `custom_oauth` + caller-rights; make it write reliably (and log failures).
- **Gain:** warm `prepare` survives restarts and is shared across instances.

### 2.3 Session-cache hardening
- Add **reconnect-on-failure** to the OAuth cache path (`snowflake.py:349`); **evict on token refresh**; consider a small healthcheck interval instead of `0`.

### 2.4 Dedupe overlapping recompute
- `prepare`, `evaluate`, and the learning build each recompute overlapping FIR/semantic/learning context. **Compute once per selection and reuse** — this is *dedup, not truncation*; the agent's context content is unchanged.

### 2.5 Optional (flagged OFF): agent prompt/model tuning
- Trim redundant prompt payload; constrain output size where the UI doesn't need a 500 kB narrative; **optional** model tiering (`claude-haiku` for trivial routing only, `claude-sonnet-4` retained for all mapping/generation). Only enable after validation. *See §6.*

## 6. Accuracy guarantee

**The plan does not compromise agent answers or accuracy.** Item by item:

| Change | Accuracy impact |
|---|---|
| 1.1 Remove rel-proc | **None** — proven empty return; relationships come from the YAML regardless. Byte-identical output |
| 1.2 / 1.3 Parallelize | **None** — same queries, same results, only concurrent |
| 1.4 Async autosave | **None to the current turn** — deferred writes feed *future* learning and still execute (with retry) |
| 0.1–0.5, 2.2, 2.3 | **None** — infra/caching/session only |
| 2.4 Dedupe | **None** — compute-once-and-reuse; content unchanged |

**Two explicit guardrails:**
1. **Keep FIR recommendations in the agent prompt.** The safe optimization is to **parallelize** the recs retrieval (agent still sees it), **not** "stream first, inject later" — that would remove it from the prompt and could change answers.
2. **Model tiering stays OFF by default** (2.5). It's the only accuracy-sensitive lever; all latency targets are met without touching the model.
