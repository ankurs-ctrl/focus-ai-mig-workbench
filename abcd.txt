## Proposed change: review Auto-map results directly in the mapping sheet

Auto-map should populate the **draft mapping sheet with its highest-confidence valid suggestion** for each target column. Users then review and adjust those suggestions directly in the sheet, rather than accepting them from a separate chat review queue. Applying a suggestion does **not** publish or finalize the mapping.

### Changes required

1. **Apply valid suggestions directly**
   - Put the strongest valid candidate into each target row automatically.
   - Low confidence alone should not prevent a suggestion from appearing.
   - Keep confidence, reasoning and any warnings visible.
   - Invalid suggestions—missing source columns, unavailable Firm Values or rules that fail validation—must remain unresolved rather than become executable mappings.

2. **Show 1–3 ranked candidates per row**
   - Each row can contain up to **three candidates total**, including the selected suggestion.
   - Add a **“View candidates”** action within the row.
   - Show each candidate’s source column(s), mapping type, confidence score, reasoning and proposed transformation rule or Firm Value.
   - Clearly identify the currently selected candidate. Do not manufacture alternatives when fewer exist.

3. **Allow users to switch candidates**
   - Selecting another candidate updates the row’s source, mapping type and associated rule together.
   - Validate the replacement before applying it.
   - Let users edit the suggestion manually, clear it or undo the AI-applied change.

4. **Keep review status in the sheet**
   - Mark newly applied suggestions as **“AI suggested — not reviewed.”**
   - Distinguish AI suggestions from user-confirmed mappings.
   - Preserve existing human-authored or confirmed mappings; show new alternatives without silently replacing those definitions.
   - Save candidate details and review status so they survive reopening the mapping.

5. **Use chat only for a summary**
   - Report how many targets received suggestions, how many have low-confidence suggestions and how many remain unresolved.
   - Keep candidate selection and row-level review entirely in the mapping sheet.

### Backend changes

The response needs **separate confidence and reasoning for each candidate**, not just a list of alternative source columns. Each candidate should represent a complete mapping option, including its rule, dependencies, Values and validation status.

**The intended workflow:** Auto-map fills the draft → users review candidates in each row → users confirm or edit → existing validation and publishing controls remain unchanged.
