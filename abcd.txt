## 8. Preserve the common payload; enforce its invariants

Do not introduce separate incompatible payloads for manual, upload, and retrigger flows.

A shared contract should represent:

- Requested target scope.
- Operation mode.
- Frozen input revision.
- Existing definitions.
- Source graph.
- Physical or derived output identities.
- Admitted bindings.
- Required dependencies.
- Exact evidence and evidence identities.
- Coverage and remaining retrieval work.
- Per-target outcomes.

### Required invariants

1. A source proposed for selection must have a verified binding in the current mapping graph.
2. Its required evidence and allowed binding must be admitted together.
3. Metadata reads alone must not automatically authorize arbitrary sources.
4. CTE parent fields must not become outer selectable fields unless independently exposed.
5. Required transformation references must be represented in the binding/evidence contract.
6. Join context and value-producing expression dependencies must have explicit semantics—not be conflated or ignored.
7. A selected-target request must not generate or apply changes outside that scope.
8. Results must remain tied to the input revision used to generate them.

An internal typed admission result shared by rendering and validation is preferable to independently reconstructing incompatible sets. Follow existing architecture rather than adding a new abstraction unless it simplifies these guarantees.

## 9. Add bounded, target-specific validation recovery

Current generic exception handling turns different failures into:

```text
Candidate failed exact mapping validation; review required
```

The specific exception message is not retained by that handler. Logs contain the exception type.

Relevant code:

```text
automap_batch.py:715–729
```

### Required recovery behavior

**Existing but unadmitted binding**

- Verify existence and graph accessibility.
- Retrieve/admit relevant evidence.
- Reevaluate or revalidate the affected target under the corrected context.
- Do not silently accept it merely because it exists.

**Unknown or ambiguous binding**

- Reject it.
- Request a bounded correction using authoritative candidates.
- Never strip a conflicting qualifier or guess between self-join aliases.

**Malformed response**

- Repair only malformed targets.
- Preserve valid siblings.
- Preserve strict source-object normalization already added in v5-1.

**Complex proposal without selected sources**

- Obtain valid source bindings first.
- Then invoke the transformation specialist if needed.

**Missing business input**

- Stop with an actionable request for the missing Value or rule.
- Do not repeatedly call the model without new information.

**Invalid expression**

- Return structured, bounded compiler feedback for repair.

Every repair must use the existing shared deadline, call accounting, and transport safety.

## 12. Retrigger freshness and stale-result protection

Existing row-level manual-edit protection and request/workspace fencing must remain intact.

However, shared inputs also matter:

- Authored SQL.
- Source membership.
- CTE outputs.
- Join predicates.
- Filters.
- Project Values.
- Relevant semantic versions.

### Required fixes

- Freeze and carry a shared-input revision through submission and result application.
- Reuse prepared context only when its relevant dependency fingerprint matches.
- Invalidate the affected prepared state when shared inputs change.
- Reject or hold results generated against an older shared-input revision.
- Preserve later manual edits even when the run was explicitly authorized to reevaluate that row.

### Specific fingerprint issue

Current code chooses SQL with a fallback resembling:

```text
compiled_mapping_sql ?? raw_mapping_sql ?? mapping_sql
```

An empty but non-null compiled value can mask authored SQL.

Do not merely replace `??` with `||`. Hash the relevant authored and compiled representations separately, with explicit rules about which inputs govern reuse.

Relevant locations:

```text
sttm-builder-slice.ts:1920 — dependency construction
sttm-builder-slice.ts:2391 — Auto-map application guards
sttm-builder-slice.ts:3078 — refresh decision
```

A deliberate retrigger is a new operation. Recovery of an ambiguously submitted request must retain its existing identity and must not create duplicate model work.
