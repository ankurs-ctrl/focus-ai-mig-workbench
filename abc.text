From the client repository root in PowerShell:

1. Upload, process, monitor, and approve through one workflow:

```powershell
.\scripts\manage_client_fir_learning.ps1 workflow `
  --file ".\docs\01-EverNest-HHs-reference.sql" `
  --project-id 1101 `
  --target-table "FFP_HDP_CRM_MIG_DB_DEV.SCH_REDTAIL_EVERNEST_TARGET.EVERNEST_HH" `
  --max-rounds 30
```

Replace the target FQN if necessary.

2. The script will display:

- SQL asset ID
- FIR learning-job ID
- Processing status
- Generated findings and recommendations
- Approval result

3. To check the job later:

```powershell
.\scripts\manage_client_fir_learning.ps1 status `
  --job-id "<LEARNING_JOB_ID>"
```

4. To continue monitoring:

```powershell
.\scripts\manage_client_fir_learning.ps1 watch `
  --job-id "<LEARNING_JOB_ID>" `
  --max-rounds 30
```

5. If it completed but was not approved:

```powershell
.\scripts\manage_client_fir_learning.ps1 approve `
  --job-id "<LEARNING_JOB_ID>"
```

Use the original EverNest SQL, not the expanded derived-source SQL. Ensure the deployed `sttm-builder` service is healthy before starting.
