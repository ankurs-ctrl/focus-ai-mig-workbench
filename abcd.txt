The main issue is that the UI mixes **having a mapping**, **validation**, and **AI review status**. A source can remain visible while an old validation/review flag makes the row appear unmapped. In the last test, retained definitions and newly applied AI proposals also followed different paths, which explains why only some rows showed AI controls.

The fix should separate those states—not simply mark every populated source as valid.

Below is a copy-ready implementation prompt.

---

# Refine mapping status, row controls, recommendations, and navigation

Update the current Auto-map review experience without changing the underlying mapping logic or weakening validation. Preserve authored mappings, transformations, CTEs, joins, filters, Values, and unsaved edits.

## 1. Remove redundant AI-status messages from the Source Column

Do not display persistent labels such as:

- “Unresolved — review suggestions”
- “AI suggested — not reviewed”
- “Unresolved — review candidates”

These labels clutter the Source Column and incorrectly imply that a populated mapping is missing.

The Source Column should primarily show the selected source column or columns. Below them, display compact blue links only when relevant:

```text
ACCOUNTS.ADDRESS1_LINE1

Reasoning    View candidates (1)    Suggestions (2)
```

Rules:

- Show **Reasoning** only when an explanation exists.
- Show **View candidates** only when genuinely different alternatives exist.
- Show **Suggestions** only when actionable guidance or relevant warnings exist.
- Do not show empty sections or placeholder candidates.
- Suggestions, uncertainty, or low confidence must not automatically make an otherwise valid mapping unmapped.
- Keep genuine blocking errors visible, with a concise explanation in the Status column or its details.

## 2. Separate mapping completeness from validation and review

Use distinct internal states for:

- **Mapping definition:** whether the row has a complete source, transformation, or Value mapping.
- **Validation:** whether that definition is valid for the current sources, joins, SQL, and Values.
- **Review/provenance:** whether it came from AI or a person and whether someone reviewed it.

These states must not overwrite one another.

### Status behavior

- **Mapped:** a complete mapping exists and its required validation is current and successful.
- **Unmapped:** no complete mapping definition exists.
- **Needs validation:** a definition exists, but validation is missing or stale.
- **Validation failed:** a definition exists but has a confirmed blocking error.

Use equivalent existing status names if available rather than introducing a competing status system.

Specifically:

- Missing AI review confirmation must not cause **Unmapped**.
- A nonblocking recommendation or confidence warning must not cause **Unmapped**.
- A failed alternative must not invalidate the current valid mapping.
- Re-running Auto-map must not discard valid status for an unchanged retained definition when its validation context is also unchanged.
- A visible source alone is insufficient to certify a mapping: missing required transformations, unresolved Values, invalid references, and required missing joins remain blockers.

Make the row status, progress bar, SQL inclusion rules, and AI summary use the same authoritative state. Clearly distinguish selected proposals from mappings actually applied to the sheet.

## 3. Simplify and standardize AI-specific buttons

Currently, some rows show **Confirm mapping**, **Undo AI change**, and **Clear suggestion**, while other AI-originated rows do not. This should not depend on whether the suggestion came from the latest run or was restored from a saved draft.

The normal row should not require a separate confirmation just because AI populated it. Applying a validated candidate should update the editable draft; publishing remains a separate operation.

Requested behavior:

- Remove the always-visible **Confirm mapping** button from normal rows.
- Use the existing row actions or overflow menu for clearing and undoing changes.
- Show **Undo AI change** only when an actual recoverable previous definition exists.
- Keep **Use candidate** inside the expanded alternatives section.
- Show **Revalidate** only when validation is genuinely required.
- Preserve AI provenance internally without adding repetitive labels to every row.
- Keep undo history separate from validation and review status.

Opening a row, confirming a choice, navigating, or autosaving must not destroy its undo history.

## 4. Keep join recommendations in two existing locations only

Join recommendations should appear in:

1. The affected mapping row’s **Suggestions** section.
2. The existing AI Assistant **bell-icon recommendations panel**.

Do not add recommendation banners or cards:

- On the Select Tables page.
- Above the join-definition section.
- Above the SQL editor.
- In additional notification surfaces or repeated pop-ups.

Both existing locations should reference the same recommendation and its current status, avoiding duplicates.

### Applying a join recommendation

Provide **Review suggested join** or **Apply recommendation**. This action opens the existing join editor with evidence-supported tables, join type, and conditions prefilled.

It must not silently save anything.

- The user reviews and explicitly saves the relationship.
- Cancel leaves the source selection, joins, SQL, and saved mapping unchanged.
- Opening the recommendation must not trigger autosave of provisional source selections.
- Do not invent missing join conditions.
- After saving, update the recommendation in both locations and indicate which mappings require revalidation.

The selection page should show the normal editor—not a second recommendation feed.

## 5. Keep confidence in its dedicated column

The selected mapping’s confidence score and bar already have a dedicated **Confidence** column. Do not repeat them in the Source Column.

Replace:

```text
Confidence and reasoning · 95%
```

with:

```text
Reasoning
```

Opening **Reasoning** should show a concise explanation, relevant evidence, and limitations.

Alternative candidates may still display their individual confidence scores inside their expanded cards, because users need those scores to compare alternatives.

Continue using readable table and column names, structured bullets, and emphasis for important entities. Do not expose generated hash aliases.

## 6. Preserve valid selection-page state when navigating back

Returning from Mapping to Select Tables should not require validation again when nothing relevant has changed.

**Next should remain enabled when the current selection/SQL context exactly matches a previously successful validation.**

Require validation again only after changes that affect that validation, including:

- SQL or CTE definitions.
- Selected source or target tables.
- Join conditions or join types.
- Driving table or population filters.
- Referenced Values or other validation dependencies.

Simply navigating back, opening an editor, expanding a panel, or viewing a recommendation must not invalidate validation.

Implementation requirements:

- Store the successfully validated context signature with the draft.
- Compare the current context against that signature.
- Associate validation responses with the exact revision they validated.
- Ignore late results from an older revision.
- If the user cancels an edit and restores the validated context, restore Next eligibility where that validation remains applicable.
- If there is no successful validation, validation failed, or dependencies changed, keep Next disabled until validation succeeds.
- Persist this behavior across autosave and reopening.

Do not implement this as a blanket “enable Next when SQL text is unchanged”; joins and other dependencies matter too.

## Acceptance tests

Verify that:

- A valid applied mapping remains **Mapped** despite suggestions or unreviewed AI provenance.
- Retained valid mappings do not become **Unmapped** merely after Auto-map or navigation.
- Incomplete and invalid definitions are not falsely certified.
- Source cells contain only sources and relevant compact links.
- Confidence appears once for the selected mapping.
- Undo appears only when a recoverable change exists.
- Join recommendations appear only in row suggestions and the existing bell panel.
- Opening and canceling join review causes no persisted changes.
- Returning to unchanged, previously validated selections leaves Next enabled.
- Relevant edits disable Next until the matching revision validates.
- Row statuses, progress totals, and summary counts agree.

**Do not change deployment configuration, agent budgets, authentication, or publishing behavior as part of this update.**
