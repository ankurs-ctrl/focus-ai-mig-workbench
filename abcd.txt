Plan: Fix AGT_SOURCE_MAPPING Auto-map (v3) and remove native v1
All paths are relative to the develop worktree ffp_ai_mig_workbench_develop_sync_20261103 (HEAD f3fbdf4 == github/develop; UAT 436167d has the same Auto-map code). This plan supersedes automap-fast-accurate-v2.

1. Context: what exists and what is broken
Why mappings fail today
Semantic descriptions are lost before the agent sees them. This happens in both UAT and develop.
_merge_native_views in semantic_model.py (277, 330-371) stores the registry YAML but never parses its dimensions / time_dimensions / facts (description, synonyms, sample_values) into attributes.
The fallback in semantic_context.py (3086-3101) then sets summary = column_name and business_meaning = None. The table description becomes "semantic asset from the registry" (1632-1636).
sttm_builder.py (3443-3458, 3248-3252) pops semantic_view (the YAML) when no executable view name resolves.
Result: ACCOUNTS has 557 described dimensions in DEV SEM_NATIVE_VIEWS.CA_YAML_MODEL, but the agent sees name echoes.
Candidate admission is lexical. In automap_fast_context.py (402-469), the score is token overlap plus 100 for an exact name match. Columns that mean the same thing under different names are never admitted.
FIR learnings are thin and not CRM-aware.
Column recipes live in TBL_FIR_TARGET_MAPPING_PATTERNS.PATTERN_PAYLOAD. They hold the full expression, sources, joins, CTE bodies, filters and $placeholders, and are written app-side at publish (project_service.py 2816/2876, 4019-4116). The scheduled FIR tasks do not write this table; they produce table-level inferences and recommendations through AGT_FIR_SYSTEM.
Retrieval gaps:
Auto-map uses discovered_only=True, so only patterns Cortex Search happened to return are eligible.
The final sort drops scope (target_mapping_patterns.py 2251-2256), and recency is never used.
Republishing never supersedes old patterns (supersession exists only in _record_correction at 905).
CRM is only payload.source_system_profile.vendor_family, which is unreliable at publish: the source system is not carried in the publish context, and HUBSPOT is missing from the fallback list (4184-4197).
CSS_AUTOMAP_RECIPES_V1 has no CRM or recency attribute.
focused_learning keeps at most 1-2 positive patterns (automap_policy.py 33-57).
The agent spec contradicts the protocol.
agent_spec_source_mapping.yaml teaches meta.delegation / search_more / CORTEX_ANALYST (40-71, 108-111). The fast path treats any delegation as a fatal batch error (automap_batch.py 668-669, 713).
The spec never describes selectable_sources or evidence_requests.
Its mode vocabulary (SOURCE|VALUE|PROJECT_VALUE) differs from the backend's (source|constant|attribute).
Values (Firm Values) are not first-class. They appear only inside global_records.source_graph.value_bindings; selectable_sources and the response example are source-only.
The transformation agent is starved. automap_transform.py (46-153) sends:
FIR expressions only if the source agent cited them;
no CTE sql_text, no samples, and no semantics outside the selection;
expression_within_selection (12-43) rejects any CASE that needs an undeclared column;
a 4500-token budget.
The runtime is over-coupled.
build_fast_model_runtime requires the parallel scan pool (AGT_AUTOMAP_SCAN_DEV_TEST, capacity 4) and OAuth or native injection (automap_runtime.py 742-757, 824-827). There is no plain local SSO path.
Native routing wins locally (sttm_builder.py 1007-1013).
The "fast" path can use 64 model calls / 8 rounds per batch.

Open-source / research assessment (context management)
Approach	Verdict	Reason
Anthropic "Contextual Retrieval" (contextual chunks, hybrid embeddings + BM25, rerank, top-20)	Adopt the pattern	Matches our problem. Column documents get their table/business context prepended; we retrieve hybrid and rerank. Cortex Search already provides hybrid retrieval with reranking inside Snowflake.
Anthropic "Effective context engineering" (smallest high-signal set; hybrid upfront plus just-in-time retrieval; sub-agents return condensed results)	Adopt the pattern	Upfront per-target evidence pack, one bounded just-in-time evidence round, and the transformation agent as a focused sub-agent.
Microsoft LLMLingua / LongLLMLingua (MIT; a small LM drops tokens, up to 20x)	Do not adopt	Token dropping corrupts identifiers, SQL and $placeholders, and it needs a local model in SPCS. Borrow only its idea of question-aware ordering: most relevant evidence first.
LlamaIndex / LangChain retrievers and compressors	Do not add as dependencies	Same functions (hybrid retrieval, rerank, dedupe, cutoff) are available natively through Cortex Search and SQL. A new framework would add an unvetted runtime to the SPCS image.
Letta / MemGPT agent memory	Not applicable	Auto-map decisions are stateless per batch; our long-term memory is the FIR tables.
Decision: build a small in-repo context assembler, a deterministic budgeted packer. Use structured, de-duplicated evidence, never lossy compression of identifiers or SQL.

2. Target design
Context budget per batch (4 targets)
Section	Content	Approx. size
Shared capsule (once per batch, identical across batches)	project/STTM description, business goal, CRM source_system_key, target table description, CTE catalog (name, purpose, outputs with meaning), join graph, Values roster ($NAME, description, resolved flag), top 3 table-level FIR recommendations	8-15 KB
Per target (x4)	target card (name, type, description, logical key, nullability); top 15 candidates with full description, synonyms, up to 5 sample values, type, table/CTE owner; learning pack (up to 4 precedents plus corrections/negatives)	6-9 KB each
Compact index	names-only list of other selected columns per table, so the agent can request more	4-12 KB
Contract	instructions pointer, response schema, 3 canonical examples (direct, Firm Value, CASE rule)	4 KB
Total is about 50-70 KB per batch. Raise AGENT_OUTBOUND_MESSAGE_MAX_CHARS for Auto-map to 150k as headroom, but have the packer target 80k or less to protect latency. The trimming order is fixed: compact index, then sample values, then candidates 15 to 10 to 6, then precedent SQL bodies down to expression-only. Descriptions of admitted candidates, the target card and Values are never trimmed.

Learning pack ranking (per target column)
Deterministic SQL over TBL_FIR_TARGET_MAPPING_PATTERNS, joined to the latest published STTM rows. Match on UPPER(TARGET_COLUMN) plus the physical target table or payload:target_contract:logical_target_key. Keep the latest per (STTM, target column) using QUALIFY ROW_NUMBER() OVER (PARTITION BY sttm_id, target_table, target_column ORDER BY publication time DESC).

Tier	Meaning	Use
T1	Same project, latest published version, or current corrections/negatives	Strongest; always included
T2	Linked project (TBL_FIR_PROJECT_LINKS)	Strong
T3	Same CRM (source_system_key / vendor_family), published, newest first	Strong if its source columns exist in the current bundle (applicable=true), else shape-only
T4	Other CRM, published	Guidance only (pattern shape, Values usage); its source column names are never offered as candidates
Each precedent carries pattern_id, CRM, project name, version, published date, expression, source columns, required joins/CTE names, placeholders, applicable (with which current columns match), and support count. If there are more than 4, keep the top 2 by tier plus the 2 most supported shapes, deduplicated by expression hash.

Where Search fits
Semantics: deterministic per-bundle ranking by default, with no index lag. Phase B adds a Cortex Search service over contextualized registry column documents (filtered by table FQN), measured by recall@15 on the answer key, and an optional AI_EMBED similarity behind a flag. Both are adopted only if they beat deterministic ranking. Note: docs/automap-context-rollout.md:256 records a missing embed grant, so grants must be verified first.
FIR: deterministic SQL for exact target-column precedents. Search (CSS_AUTOMAP_RECIPES_V1 / CSS_FIR_KNOWLEDGE) is used only as a fallback when T1-T3 return nothing, once per target, run in parallel, and labelled guidance.
Analyst: not in the main path. Sample values come from YAML / COLUMN_PROFILE_CACHE. Keep _auto_map_analyst_evidence reachable only through the single evidence round, for an explicit data question about value distribution needed by a CASE.
Time budget (37 targets)
Prep, once per job and cached by bundle hash plus target set: about 10-20 s.
10 batches, up to 8 in flight: 2 waves of about 40-50 s each, roughly 90 s.
Transformation wave (parallel, only rule targets): about 20-30 s.
Goal: about 120 s in SPCS; 150 s or less locally.
Model calls capped at 3 per batch: answer, optional evidence round, optional format repair. This replaces the current 64 calls / 8 rounds.

Step 4: Candidate ranking, evidence pack and context packer
Hybrid ranker in automap_candidates.py, combining by reciprocal rank fusion:

exact or normalized name match and synonyms;
BM25-style token score over the contextualized document "table description | column | description | synonyms";
type compatibility;
FIR applicable-precedent source columns (forced in);
user joins / CTE outputs feeding the target table;
optional Phase B search or embedding signal.
It returns the top 15 per target, with a short reason per candidate (for example "synonym", "precedent T1", "description match").

Shared capsule builder: business context from workspace_context, the CRM, the target table description from the target bundle, a CTE catalog with purpose and output meaning (full sql_text only for the transformation agent), the join graph, a first-class Values roster, and FIR table-level recommendations for the target FQN (TBL_FIR_AGENT_RECOMMENDATIONS / SP_FIR_GET_AGENT_RECOMMENDATIONS_V2).

Budgeted packer in automap_context_packer.py: a fixed section order (most relevant first), deterministic trimming, stable record IDs (src:<table>.<col>, cte:<name>.<col>, val:$NAME, fir:<pattern_id>), and a context_manifest (sizes, trimmed sections) logged per batch.

Replace FastContextPlan lexical admission (automap_fast_context.py 402-469) with the ranker output.

Collapse the decision loop to 3 calls or fewer per batch (MAX_FAST_MODEL_CALLS, MAX_FAST_DECISION_ROUNDS).

Make meta.delegation a soft deficit, not a fatal error (automap_batch.py 668-669, 713). One evidence_requests round returns full catalog entries for up to 10 named columns per target.

Step 6: AGT_SOURCE_MAPPING fast-only protocol, spec and runtime
Rewrite the spec (agent_spec_source_mapping.yaml): remove the delegation and tool text, and describe the packet sections and record IDs. Decision procedure per target:
understand the target meaning;
read the candidates' descriptions, synonyms and samples;
check the business goal and CTE purpose;
weigh precedents by tier and applicability;
choose source | attribute ($Value) | constant | rule_needed | unresolved.
Response per target: mapping_mode, sources or $NAME, decision_basis (cites candidate and precedent IDs plus a one-line semantic reason), precedent_decision (followed / adapted / rejected with reason) whenever precedents exist, rule_intent (natural-language rule plus required columns) when a CASE or custom rule is needed, and evidence_request (optional, once).
Align the mode vocabulary with the backend schema. Add 3 canonical few-shot examples.
Server-side "read" enforcement: every cited ID must exist in the packet. When precedents exist, precedent_decision is required. A target answered with no valid citation is downgraded to review. This is the read-receipt equivalent without tool loops.
Model: benchmark claude-haiku-4-5 against a stronger model available on the account, under the same packet. Choose by accuracy within the time budget.
Deployment: extend scripts/sync_workbench_agent_specs.py to allow approved model/budget changes (an explicit flag plus a diff report), and update agent_spec_manifest.json hashes. deploy_spcs_client_snow_safe.ps1 already hashes the spec files (311-317).
Runtime:
make build_fast_model_runtime independent of the scan pool (automap_runtime.py 742-757, 824-827);
support SPCS OAuth plus local SSO through automap_local_session.py;
make in-flight count and pool capacity configurable (default 8);
set a per-batch deadline of 60 s and a job deadline of 180 s;
cache the prep artifacts per job.
