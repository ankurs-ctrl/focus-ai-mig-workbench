## 1. Repo file — real, permanent code fix

**`scripts/deploy_spcs_client_snow_safe.ps1`** — the `Invoke-Checked` function

**Problem:** Under Windows PowerShell 5.1, when this script's output is captured (background job, `*>` redirect, transcript), `$ErrorActionPreference = "Stop"` (set earlier in the same file) causes *any* stderr text from `snow.exe` — even a routine "Initiating login request..." SSO message — to be treated as a fatal error, aborting the whole deployment even though `snow.exe` actually succeeded (exit code 0). This is what caused several of the retries.

**Before:**
```powershell
function Invoke-Checked {
    param(
        [scriptblock]$Command,
        [string]$Description
    )

    Write-Host ""
    Write-Host "==> $Description"
    & $Command
    $exitCode = $LASTEXITCODE

    if ($null -ne $exitCode -and $exitCode -ne 0) {
        throw "$Description failed with exit code $exitCode"
    }
}
```

**After:**
```powershell
function Invoke-Checked {
    param(
        [scriptblock]$Command,
        [string]$Description
    )

    Write-Host ""
    Write-Host "==> $Description"

    # Native commands (e.g. snow.exe) write routine progress/warning text to
    # stderr. Under Windows PowerShell 5.1, when this script's own output is
    # captured/redirected (Start-Job, *>, transcripts, etc.), those benign
    # stderr lines get promoted into terminating NativeCommandError exceptions
    # while $ErrorActionPreference = "Stop" is active, even though the actual
    # process exit code is 0. Temporarily relax the preference around the call
    # and rely solely on $LASTEXITCODE (below) to detect real failures.
    $previousEap = $ErrorActionPreference
    $ErrorActionPreference = "Continue"
    try {
        & $Command
    } finally {
        $ErrorActionPreference = $previousEap
    }
    $exitCode = $LASTEXITCODE

    if ($null -ne $exitCode -and $exitCode -ne 0) {
        throw "$Description failed with exit code $exitCode"
    }
}
```
This is the only actual source-code change I made in the repo. Everything else below is config or ad-hoc deployment tooling.
