# Code Changes I Made This Session

## 1. Core production bug fix — Cortex Analyst identifier quoting

**File**: `services/sttm-builder/app/core/semantic_context.py`

**Problem**: semantic view YAML built column references as `expr: BillingCity` (unquoted). Snowflake case-folds unquoted identifiers to uppercase, but the physical column was created as `"BillingCity"` (quote-preserved mixed case) — so Cortex Analyst generated SQL referencing a nonexistent `BILLINGCITY` column, failing with `invalid logical column name` / `invalid identifier`.

**Fix** — added a helper (new code, line 3843):
```python
def _quoted_column_expr(column_name: str) -> str:
    """Quote a physical column reference so mixed-case/quoted-identifier columns
    (e.g. "BillingCity") resolve correctly instead of being folded to uppercase
    by Snowflake's unquoted-identifier rules."""
    escaped = str(column_name).replace('"', '""')
    return f'"{escaped}"'
```

Applied at two call sites:

**Dimension/fact builder** (line ~2542-2547):
```python
entity = {
    "name": attribute["name"],
    "description": entity_description,
    "expr": _quoted_column_expr(attribute["name"]),   # was: attribute["name"]
    "data_type": attribute["data_type"],
}
```

**Metric aggregate expression builder** (line ~2581-2587):
```python
if aggregate_function:
    quoted_column = _quoted_column_expr(attribute["name"])
    metric_expr = (
        f"COUNT(DISTINCT {quoted_column})"
        if aggregate_function == "COUNT_DISTINCT"
        else f"{aggregate_function}({quoted_column})"
    )
```
Verified live against the real Cortex Analyst API — reproduced the original failure with an unquoted test, confirmed the quoted version generates and executes valid SQL.

## Issue A: `_quote_literal` doesn't escape backslashes → SQL compile error on bundle persistence

**File**: `services/sttm-builder/app/core/semantic_context.py:3711`
```python
def _quote_literal(value: str) -> str:
    return "'" + value.replace("'", "''") + "'"
```
Only escapes single quotes. Snowflake string literals interpret backslash escapes (`\uXXXX` etc.) by default. Used to interpolate several fields directly into SQL text at `_upsert_bundle` (line ~3316-3387):
```python
{_quote_literal(bundle_label)} AS BUNDLE_LABEL,
...
{_quote_literal(semantic_view_name or "")} AS SEMANTIC_VIEW_NAME,
{_quote_literal(semantic_model_yaml or "")} AS SEMANTIC_MODEL_YAML,
...
{_quote_literal(stale_reason or "")} AS STALE_REASON,
```
Any of these containing a literal `\u`-style sequence breaks with:
```
SQL compilation error: Invalid unicode escape sequence '\u201353500'; should be at most '\u0010FFFF'.
```
**Suggested fix**: switch these to bind parameters (`?`) the same way the JSON fields already do (`PARSE_JSON(?)`), instead of string-interpolating via `_quote_literal`.

## Issue B: Frontend swallows specific validation messages, shows generic error

**File**: `frontend/src/api/errors/app-error.ts:33-44`
```typescript
function readEnvelopeError(data: unknown): ApiError | null {
  if (typeof data !== 'object' || data === null) {
    return null;
  }
  const envelopeError = (data as { error?: ApiError | null }).error;   // only checks `.error`
  if (envelopeError && typeof envelopeError === 'object') {
    return envelopeError;
  }
  return null;
}
```
This only recognizes your app's own envelope shape (`{error: {detail, code, ...}}`). But `services/sttm-builder/app/routers/mapping_sql.py:41-42` raises a bare FastAPI exception:
```python
except ValueError as exc:
    raise HTTPException(status_code=400, detail=str(exc)) from exc
```
which returns `{"detail": "Target RECORDTYPEID is not mapped."}` — no `error` wrapper. So `parseAppError` (`app-error.ts:94-100`) falls through every check and lands on the generic Axios message (`"Request failed with status code 400"`), hiding the actual actionable reason from the user.

**Suggested fix**: in `readEnvelopeError`, also check for a bare top-level `detail` string when `.error` isn't present:
```typescript
function readEnvelopeError(data: unknown): ApiError | null {
  if (typeof data !== 'object' || data === null) return null;
  const envelopeError = (data as { error?: ApiError | null }).error;
  if (envelopeError && typeof envelopeError === 'object') return envelopeError;
  const bareDetail = (data as { detail?: unknown }).detail;
  if (typeof bareDetail === 'string') return { detail: bareDetail } as ApiError;
  return null;
}
```
