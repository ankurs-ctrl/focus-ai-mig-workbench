Do not rely on `deploy_spcs_client_snow_safe.ps1` alone for FIR. It deploys the application/services; FIR’s Snowflake tables, procedures, streams, grants, and tasks need their own deployment step.

Yes, this ZIP changes Snowflake-side FIR assets:

- FIR stream definitions and stream recreation handling.
- FIR grants.
- `SP_FIR_INVOKE_AGENT` timeout/execution behavior.
- FIR learning/retrieval behavior used by the agents.
- New CRM target-contract support in application metadata.
- Semantic registry/model assets and related agent specifications.

Recommended client deployment order:

1. Extract the ZIP into the repository root.

2. Merge the target settings from `TARGET-CONTRACT-ENV.example` into the client’s existing environment/secrets. Do not overwrite `.env.local`.

3. Deploy FIR objects first, while tasks remain suspended:

```powershell
bash ./infra/snowflake/scripts/deploy-fir-system.sh --skip-tasks
```

4. Because your client FIR streams are disabled/stale, recreate them only after confirming FIR tasks are suspended:

```powershell
bash ./infra/snowflake/scripts/deploy-fir-system.sh --recreate-streams
```

This resets stream offsets. It is appropriate here because you said FIR streams are disabled; it avoids resuming tasks against old stream positions.

5. Deploy/redeploy the application normally:

```powershell
.\scripts\deploy_spcs_client_snow_safe.ps1
```

6. After confirming the app is healthy and the FIR tables/procedures/streams exist, resume FIR tasks:

```powershell
bash ./infra/snowflake/scripts/deploy-fir-system.sh --tasks-only --resume-tasks
```

You do not need to run the full initial bootstrap script if the client environment already has the existing STTM/FIR base tables. The FIR deploy script is additive and handles the upgraded FIR schema/procedures. Run the semantic-model bootstrap only if the client does not already have the semantic registry / `AGT_SEMANTIC_MODEL_V2` assets, or if deployment reports they are missing.
