## 2. Why the references weren’t converted correctly

There are three connected code gaps.

### A. Citation generation and normalization disagree

The citation helper generates an unquoted identifier:

```text
accounts_80ydxi."ADDRESS1_LINE1"
             ↓
src:accounts_80ydxi.ADDRESS1_LINE1
```

But the source normalizer recognizes the catalog record ID or `src:` followed by the **exact quoted catalog reference**. It does not resolve this unquoted citation spelling, so the `src:` reference survives.

Relevant files:
- `services/sttm-builder/app/core/automap_citations.py:20`
- `services/sttm-builder/app/core/automap_source_format.py:20`

### B. Rule dependencies can carry the same invalid references

`rules-v2` copies `rule_intent.required_columns` into the transformation dependencies without resolving those citations first.

Consequently, even if selected source references are corrected, unresolved intent references can introduce the problem again.

Location: `services/sttm-builder/app/core/automap_batch.py:825`.

### C. The earlier check skips physical-table drivers

The preliminary source-binding check returns early when the driving table is physical. This mapping’s driver is `ACCOUNTS`, so the malformed references survive until transformation packet construction.

Location: `services/sttm-builder/app/core/sttm_builder.py:1464`.

## 5. What should be fixed

1. **Resolve citations consistently** to one authorized catalog `source_ref`, preserving quoting and table-instance identity.
2. Apply that resolution to source attributes, dependencies, **and `rule_intent.required_columns`**.
3. Validate bindings for physical drivers as well as derived sources.
4. Return a target-specific validation error and preserve the exception message instead of logging only `ValueError`.

**Do not blindly strip `src:`**—the reference must first resolve uniquely against the allowed source catalog.
